## 追加（第五轮）：整体架构重构为 React + Vite（用户四条要求）

### 需求
1. 优化整体架构为 React，使用 Vite 构建。
2. 弹出的诗词卡片要居中，且点击地图区域自动关闭。
3. 抽屉点击外侧地图也要自动关闭。
4. 优化性能表现。

### 架构决策：**React 只管界面外壳，地图/三维保持命令式单例**
不全盘 React 化。Leaflet 管着上千节点与自己的事件/投影系统，Three.js 管着 WebGL 上下文——
塞进 React diff 只会带来双重真相与整片重挂载。最终分两层：

```
声明式外壳(React 组件) ──useSyncExternalStore──> src/store.js（单一真相）
                                  ↑ subscribe()
命令式引擎(Leaflet / Three / GSAP / 地形 / 定位) ──┘
```
React 重渲染不碰地图；地图平移也不上抛状态。共享的只有「筛选条件 / 选中项」两件事。

### 目录
- `src/store.js`：`getState/subscribe/useStore(key)`，动作全走 `setState`。
- `src/data/`：`poems.tang/song.js`、`authors.js`、`tags.js`、`china.geo.js`、`geo-extras.js`
  （以上由 `tools/port-to-esm.js` 机械迁移，**逐字段校验过完全一致**）+ 新写的 `places.js`（地标聚合，确定性取名）、
  `select.js`（筛选纯函数）、`index.js`（聚合入口）。

  `terrain.js`/`thumbs.js`/`mapimage.js`/`atmosphere.js`/`motion.js`/`eave.js`（原 `js/*` 转 ESM）。
- `src/components/`：12 个（Brand/Tools+MenuPop/Sidebar/BottomBar/Card/PoemList/Detail/Panel/Toast/Chrome/Paint/icons）。

### 踩坑（都值得记）
- **Vite 8 走 rolldown，`manualChunks` 只认函数形式**——写对象会 `manualChunks is not a function` 直接构建失败。已改函数。
- **`App.jsx` 深链分支两处笔误**（DEV 下这条分支从没被跑到，一构建就露）：
  `POEMS_BY_ID`（真名 `POEM_BY_ID`）+ `openDetailFromHash()` 根本没定义。已改为 `openFromHash(engine)` 模块级函数，
  并补 `hashchange` 监听，让粘贴地址/前进后退都能开。
- **Vite 用 `import.meta.env.DEV` 判定**，devtools 钩子在生产被 tree-shake（已验证 `window.__store === undefined`）。
  所以 `tools/probes/*` 一律只读 DOM 与 `window.__perf`，才能在 dev 与 preview 上都跑。
- **`--eval` 报 SyntaxError 是引号地狱**：cdp.js 支持 `--eval @tools/probes/xxx.js`（脚本文件），长表达式一律写文件。
- **`tools/steps/pick.js` 的参数格式是单槽 `"名字|last"`**（用 `|` 分隔名与兜底），不是两槽。之前误用两槽导致 pick 收到空名直接返回 null。
- **探针易选错元素**：诗词卡的竖排落在 `.c-poem .col`（每列一个 span），容器 `#cardPoem` 只负责 `flex-direction:row-reverse`；
  抽屉 `.d-poem` 才直接竖排。别量容器。

## 追加（第六轮）：修 bug —— 点地图收面板时卡片「闪一下」

### 现象（用户报）
开卡 → 点「查看完整注解」进抽屉 → 点地图：抽屉收起，但**卡片闪现了一下**。

### 根因：不是渲染性能，是「两条关闭路径跑在两个事件阶段」
卡片是否显示 = `!!openPoemId && !poemListPlaceId && !detailPoemId`，而 `openDetail()` 会**保留** `openPoemId`
（设计意图：关抽屉要回到卡片，已验证）。于是点地图时：

| 时序 | 事件 | 当时的调用 | 状态 | 画面 |
| --- | --- | --- | --- | --- |
| t0 | `pointerdown`（App.jsx 的 DOM 兜底） | 只 `closeDetail()` | `detailPoemId` 空了、`openPoemId` 还在 | 卡片条件变真 → **卡片冒出来** |
| t1 | `click`（Leaflet `map.on("click")`） | `closeCard()` 等 | `openPoemId` 空了 | 卡片又消失 |

t0 与 t1 之间浏览器画了一帧 → 闪现。又因卡片 `on` 变化触发 `MOTION.cardIn()`，闪现还带入场动画。
实测闪现 **4 帧 ≈ 67ms**。

### 修法：收敛成一次原子状态变更
- `src/store.js` 新增 `dismissOverlays()`：**一次** `setState` 清掉
  `activePlaceId / openPoemId / poemListPlaceId / detailPoemId / notesOpen`。
- 两个入口共用：`mapEngine.js` 的 `map.on("click")` 与 `closeAll`，`App.jsx` 的 `pointerdown` 兜底，
  `actions.js` 的 `resetView()`（原来也是三次 setState，顺序恰好不闪但多渲染两轮）。
- 谁先跑谁清干净，后跑的因状态无变化被 `setState` 的 changed 判断挡掉 → 不产生额外渲染。
- 结果：闪现 **4 帧 → 0 帧**；已用临时还原旧代码做 A/B 对照，确认探针真能抓到（timeline `0:-D 1:C- 2:C- 3:C- 4:C- 5:--` vs 修复后 `0:-D 1:-- 2:-- …`）。

### 关键教训：这个 bug **躲过了之前所有自动化验证**
`tools/steps/_pre.js` 的 `__press()` 把 `pointerdown / mousemove / mouseup / click` 在**同一个任务**里同步发完，
React 批处理成一次提交，中间**没有绘制帧** → 永远测不出中间态。真实用户按下与抬起隔着几十毫秒，浏览器会画一帧。
→ **测交互时序问题，「两个事件之间的那一帧」才是被测对象。**
以后凡是「先 A 后 B」的关闭/切换逻辑，探针都要把两段拆到不同帧再逐帧采样 DOM。

### 新增探针
- `tools/probes/dismiss-flash.js`：pointerdown 与 click 分帧发，逐帧采样 `#card`/`#detail` 的 `.on`，
  返回 `cardFlashedFrames` / `cardFlashDetected` / `timeline`。
- `tools/probes/dismiss-paths.js`：回归三条既有设计意图 ——
  ① 点抽屉关闭按钮 → 只关抽屉、**卡片回来**；② Esc 逐层收（第一下抽屉+卡片回来，第二下才关卡片）；
  ③ 点地图 → 卡片+浮层+抽屉全关。全部通过。
- README 第五节「交互要点」、第三节目录、第七·五节（新增「卡片为什么会闪一下」小节）、第十节验证命令已同步。

### 一个已知的行为微变（可接受）
抽屉/浮层开着时，在地图上**按下即拖**（不产生 click）现在会一并收起全部面板；修复前是「抽屉关、卡片复活并留着」。
新行为更一致（开始操作地图＝收起覆盖层），且只在抽屉/浮层开着时生效——只开卡片时拖地图不受影响（监听器当时未挂载）。
